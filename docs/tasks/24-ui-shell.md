## Goal

`web/` is a React + TypeScript + Vite app that the hub embeds and serves at `/`. A first visit shows first-run setup; afterwards login. Logged in, the user sees a quiet app shell with navigation to the seven screens; each screen is a header plus an empty state (Hairline illustration) that later tasks replace. All data comes through a client generated from `api/openapi.yaml`.

### Behaviour

- **Guard:** on load call `GET /api/setup`. If `needed`, every route redirects to `/setup`. Otherwise `GET /api/me`; a 401 redirects to `/login?next=<path>`. After login or setup, go to `next` or `/`.
- **Setup:** email, name, password (min 12, show the rule), confirm password. Submit `POST /api/setup`; on 409 go to `/login`.
- **Login:** email and password, submit `POST /api/auth/login`; show 401 as "Email or password is wrong" and 429 as "Too many attempts, try again in a few minutes". Hairline illustration beside the form on wide screens.
- **Shell:** sidebar items in this order: Overview `/`, Quotas `/quotas`, Accounts `/accounts`, Usage `/usage`, Alerts `/alerts`, Machines `/machines`, Settings `/settings` (Settings only for admins: `me.user.role === "admin"`). Top bar: page title, theme toggle, user menu (name, email, role, Log out → `POST /api/auth/logout` then `/login`).
- **Footer:** `aicm <version> · Source` where version comes from `GET /healthz` and Source links to `source_url` from `GET /api/settings` when available, else `https://github.com/atakanatamert/aicm` (AGPL network clause). Keep the product name in one constant `APP_NAME = "aicm"` in `src/lib/brand.ts`.
- **Screens:** each of the seven routes renders a page header (title + one-line description) and `<EmptyState>` with a short sentence about what will appear there. No fake data.
- **Look:** quiet and neutral (shadcn neutral base), one accent color reserved for urgency (define it as a CSS variable `--urgent`, unused yet except in the theme). Dense but readable. Motion only for the sidebar collapse and page fade (≤150 ms).
- **No hand-written fetch** and no hand-written response types: every call goes through `api/client.ts` with types from `schema.d.ts`.

Cache headers: `Cache-Control: public, max-age=31536000, immutable` for files under `assets/`, `no-cache` for `index.html`.

`httpapi.NewRouter`: create the base `http.ServeMux`, register `mux.Handle("GET /", d.Web)` when `d.Web != nil`, then pass the mux as `BaseRouter`. API routes are more specific and keep winning. Unknown `/api/...` paths must still return the JSON 404 envelope: register `mux.HandleFunc("/api/", …WriteError(404, "not_found", …))`.

`Dockerfile`: add a first stage `FROM node:22-alpine AS web` that enables corepack, runs `pnpm install --frozen-lockfile` and `pnpm build` in `/web`, and copy `/web/dist` into the Go build stage at `web/dist` before `go build`.

CI `web` job: setup node 22 + pnpm, `pnpm -C web install --frozen-lockfile`, `pnpm -C web gen:api` then `git diff --exit-code web/src/api/schema.d.ts`, `pnpm -C web lint`, `pnpm -C web build`.
